  <name>Task 2: Build and activate the Telegram echo workflow in n8n via API</name>
  <files></files>
  <action>
    Build a single n8n workflow using the n8n REST API. The workflow has 6 nodes:

    **Workflow: "Telegram AI Assistant - Echo (Phase 1)"**

    ```
    [Telegram Trigger] -> [Code: Whitelist Check] -> [IF: Is Allowed?]
      YES -> [HTTP Request: Log to CRM (allowed)] -> [Telegram: Send Echo Reply]
      NO  -> [HTTP Request: Log to CRM (rejected)]
    ```

    **Node 1: Telegram Trigger**
    - Type: `n8n-nodes-base.telegramTrigger`
    - Credential: "Telegram Bot - Bigterrys" (ID from Task 1)
    - Updates: ["message"] (only text messages in Phase 1)

    **Node 2: Code: Whitelist & Stale Check**
    - Type: `n8n-nodes-base.code`
    - JavaScript (executed in n8n runtime, NOT in browser):
    ```javascript
    const chatId = String($input.item.json.message.chat.id);
    const allowedChatIds = $env.TELEGRAM_ALLOWED_CHAT_IDS
      ? $env.TELEGRAM_ALLOWED_CHAT_IDS.split(',').map(id => id.trim())
      : [];

    const isAllowed = allowedChatIds.includes(chatId);
    const messageDate = $input.item.json.message.date;
    const now = Math.floor(Date.now() / 1000);
    const isStale = (now - messageDate) > 120;

    return {
      json: {
        chatId,
        isAllowed,
        isStale,
        shouldProcess: isAllowed && !isStale,
        messageText: $input.item.json.message.text || '',
        messageId: $input.item.json.message.message_id,
        userName: $input.item.json.message.from.first_name || 'Unknown',
        timestamp: messageDate,
      }
    };
    ```

    **IMPORTANT n8n environment variable setup:** The `TELEGRAM_ALLOWED_CHAT_IDS` variable must be set as an n8n environment variable (not just Doppler). Either:
    - Set it in the n8n App Platform environment variables (DO Console -> Apps -> n8n -> Settings -> Environment Variables)
    - Or use an HTTP Request to fetch it from the CRM at workflow start

    The simpler approach: Hardcode the chat ID in the Code node for Phase 1. Store the allowed chat IDs as a constant inside the Code node itself:
    ```javascript
    const ALLOWED_CHAT_IDS = ['HARRIS_CHAT_ID_HERE'];
    ```
    Replace `HARRIS_CHAT_ID_HERE` with the actual chat ID from Doppler. This avoids the n8n env var complexity and is appropriate for single-user Phase 1.

    **Node 3: IF: Should Process?**
    - Type: `n8n-nodes-base.if`
    - Condition: `{{ $json.shouldProcess }}` equals `true`

    **Node 4a (TRUE path): HTTP Request: Log Allowed Message**
    - Type: `n8n-nodes-base.httpRequest`
    - Method: POST
    - URL: `https://walrus-app-8dgas.ondigitalocean.app/api/assistant/bot-log` (production CRM URL)
    - **Authentication: Use the "CRM Assistant API Key" HTTP Header Auth credential (created in Task 1, Step 3c).** In the node configuration, set:
      - `authentication`: `httpHeaderAuth`
      - `credential`: reference the "CRM Assistant API Key" credential by ID
    - This automatically adds the `X-Assistant-Key: <ASSISTANT_API_KEY>` header to every request. Do NOT hardcode the API key in the node's header parameters.
    - Body (JSON):
    ```json
    {
      "chat_id": "{{ $('Code: Whitelist Check').item.json.chatId }}",
      "message_text": "{{ $('Code: Whitelist Check').item.json.messageText }}",
      "route_taken": "echo",
      "response_text": "Echo: {{ $('Code: Whitelist Check').item.json.messageText }}",
      "processing_time_ms": 0,
      "metadata": {
        "user_name": "{{ $('Code: Whitelist Check').item.json.userName }}",
        "message_id": "{{ $('Code: Whitelist Check').item.json.messageId }}"
      }
    }
    ```
    - Error handling: Continue on failure (logging failure should not prevent the echo reply)

    **Node 5 (after 4a): Telegram: Send Echo Reply**
    - Type: `n8n-nodes-base.telegram`
    - Credential: "Telegram Bot - Bigterrys" (same as trigger)
    - Operation: sendMessage
    - Chat ID: `{{ $('Code: Whitelist Check').item.json.chatId }}`
    - Text: `Received: {{ $('Code: Whitelist Check').item.json.messageText }}`
    - Parse Mode: Markdown

    **Node 4b (FALSE path): HTTP Request: Log Rejected Message**
    - Type: `n8n-nodes-base.httpRequest`
    - Method: POST
    - URL: `https://walrus-app-8dgas.ondigitalocean.app/api/assistant/bot-log`
    - **Authentication: Use the same "CRM Assistant API Key" HTTP Header Auth credential (same as Node 4a).** Set `authentication: httpHeaderAuth` and reference the credential by ID.
    - Body (JSON):
    ```json
    {
      "chat_id": "{{ $('Code: Whitelist Check').item.json.chatId }}",
      "message_text": "{{ $('Code: Whitelist Check').item.json.messageText }}",
      "route_taken": "rejected",
      "metadata": {
        "reason": "{{ $('Code: Whitelist Check').item.json.isStale ? 'stale_message' : 'unauthorized_chat_id' }}",
        "user_name": "{{ $('Code: Whitelist Check').item.json.userName }}"
      }
    }
    ```
    - No Telegram reply node on this path (silent rejection)

    **Build the workflow JSON and deploy via n8n API:**

    When constructing the workflow JSON, ensure both HTTP Request nodes (4a and 4b) reference the "CRM Assistant API Key" credential. The credential reference in the workflow JSON looks like:
    ```json
    {
      "credentials": {
        "httpHeaderAuth": {
          "id": "<CRM_ASSISTANT_API_KEY_CREDENTIAL_ID>",
          "name": "CRM Assistant API Key"
        }
      }
    }
    ```
    Replace `<CRM_ASSISTANT_API_KEY_CREDENTIAL_ID>` with the actual ID returned from Task 1 Step 3c.

    ```bash
    N8N_API_KEY=$(doppler secrets get N8N_API_KEY --project mortgage-crm --config dev --plain)
    N8N_URL=$(doppler secrets get N8N_API_URL --project mortgage-crm --config dev --plain)

    # Create the workflow
    curl -X POST "$N8N_URL/api/v1/workflows" \
      -H "X-N8N-API-KEY: $N8N_API_KEY" \
      -H "Content-Type: application/json" \
      -d @workflow.json

    # Activate the workflow (replace WORKFLOW_ID with the returned ID)
    curl -X PATCH "$N8N_URL/api/v1/workflows/WORKFLOW_ID" \
      -H "X-N8N-API-KEY: $N8N_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"active": true}'
    ```

    **CRITICAL:** Only ONE workflow can use the Telegram Trigger for this bot token. Activating a second workflow with a Telegram Trigger will overwrite the webhook and break this one. If any test workflows with Telegram Trigger exist, deactivate them first.

    **After activating**, the n8n Telegram Trigger node automatically calls `setWebhook` on the Telegram API, registering the n8n webhook URL. No manual webhook setup is needed.

    **Note on production CRM URL:** The API endpoints must be deployed to production (pushed to main branch, which triggers auto-deploy on DO App Platform) before the n8n workflow can reach them. If the endpoints are only on localhost, the n8n workflow (running on DO) cannot reach them. Ensure the Plan 01 code changes have been pushed to main and deployed before activating this workflow.
